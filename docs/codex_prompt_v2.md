# CODEX PROMPT — نظام إدارة الجودة والاعتماد الأكاديمي المتكامل
### النسخة النهائية الشاملة

---

## قاعدة صارمة — التصميم والألوان

> **لا تكتب أي لون hardcoded (hex, rgb, اسم لون) في أي مكان.**
> استخدم **حصراً** الـ CSS variables والـ utility classes الموجودة في الـ Design System الحالي للمنصة.
> كل Badge وCard وButton وAlert يجب أن يستخدم المكونات الجاهزة الموجودة في codebase.
> إذا كان المشروع يستخدم Tailwind — استخدم الـ classes الموجودة في `tailwind.config`.
> إذا كان يستخدم CSS variables — استخدم المتغيرات المعرّفة في `:root`.
> إذا كان يستخدم مكتبة UI (shadcn / PrimeVue / Ant Design / إلخ) — استخدم مكوناتها فقط.
> **لا استثناءات لهذه القاعدة.**

---

## السياق العام

أنت تعمل على **توسعة نظام ويب موجود**. النظام يحتوي على:
- Layout ثابت (Sidebar + Header + Main Content Area)
- Design System مكتمل مع مكونات UI جاهزة
- نظام Routing قائم
- نظام Authentication وRoles موجود

المطلوب: إضافة **ثلاثة موديولات جديدة** متكاملة مع النظام الحالي دون تعديل أي شيء موجود إلا بالإضافة فقط.

---

## قواعد الكود العامة — تُطبَّق على كل موديول

```
1. استخدم نفس Base Layout الحالي بدون تعديل
2. استخدم المكونات الجاهزة في الـ codebase للـ Cards والـ Tables والـ Badges والـ Modals والـ Buttons
3. لا تنشئ مكونات جديدة إلا إذا لم يوجد ما يغطي الحاجة، وفي هذه الحالة التزم بنفس أسلوب كتابة المكونات الموجودة
4. كل جدول يدعم: Search + Sort + Pagination
5. كل Form يتضمن Validation مع رسائل خطأ واضحة
6. سجلات الـ Log / Timeline لا تُحذف ولا تُعدّل (Immutable)
7. كل إجراء يُسجَّل بـ Timestamp دقيق (تاريخ + وقت)
8. جميع التواريخ تُخزَّن وتُعرض بصيغة YYYY-MM-DD
9. التزم بنظام الـ Roles الموجود في المشروع — لا تنشئ نظام صلاحيات جديد
10. Dummy Data تكون واقعية: كليات وبرامج أكاديمية حقيقية، تواريخ منطقية
11. وثّق كل ملف جديد بتعليق في أول السطر يوضح الغرض منه
12. ابدأ بالموديول الأول كاملاً ثم انتقل للثاني ثم الثالث
```

## الموديول الأول: إدارة الاعتماد الأكاديمي

### 1.1 لوحة التحكم — `/accreditation/dashboard`

**الغرض:** رؤية فورية وشاملة لحالة جميع البرامج الأكاديمية.

**المحتوى:**

بطاقات إحصائية (Summary Cards) — استخدم مكون الـ Card الموجود:
- إجمالي البرامج
- عدد البرامج بـ "اعتماد كامل"
- عدد البرامج بـ "اعتماد مشروط"
- عدد البرامج "المؤهلة للاعتماد"
- عدد البرامج "غير المؤهلة"

مخطط دائري (Donut/Pie Chart) لتوزيع الحالات — استخدم مكتبة الـ Charts الموجودة في المشروع.

آلية Drill-down:
- عند الضغط على أي شريحة في الـ Chart → تظهر قائمة البرامج المفلترة بتلك الحالة في الأسفل
- عند الضغط على حالة اعتماد في أي جدول → ينتقل للصفحة المناسبة مع الفلتر مفعّلاً

جدول آخر التحديثات:
- الاسم / الكلية / الحالة (Badge) / آخر تحديث
- الأعمدة قابلة للترتيب
- عرض آخر 10 تحديثات مع رابط "عرض الكل"

**ملاحظة تقنية:** هذه الصفحة للعرض فقط (Read-only) — تتغذى تلقائياً من بيانات صفحة Master Data.

### 1.2 بيانات البرامج (Master Data) — `/accreditation/programs`

**الغرض:** المرجع الرئيسي لجميع معلومات البرامج الأكاديمية.

**هيكل البيانات لكل برنامج:**
```
- اسم البرنامج (Program Name)
- الكلية (College)
- المرحلة الدراسية: بكالوريوس / ماجستير / دكتوراه (Degree Level)
- جهة الاعتماد (Accreditation Body)
- حالة الاعتماد: اعتماد كامل / مشروط / مؤهل / غير مؤهل (Status)
- تاريخ بداية الاعتماد
- تاريخ نهاية الاعتماد
- تاريخ آخر تحديث (auto)
- المستخدم الذي أجرى آخر تحديث (auto)
```

**الجدول الرئيسي:**
- عرض جميع الحقول أعلاه
- فلاتر بالأعلى: الكلية + المرحلة + الحالة + جهة الاعتماد
- Search بالاسم
- Pagination
- زر "إضافة برنامج" — يفتح Modal بالحقول أعلاه مع Validation
- لكل صف: زر "تفاصيل" + زر "تعديل" + زر "حذف" (بتأكيد)

**صفحة تفاصيل البرنامج** `/accreditation/programs/{id}`:
- عرض جميع بيانات البرنامج
- التنقل المباشر لصفحات: المتطلبات / سجل الإجراءات / ما بعد الاعتماد — كلها مفلترة لهذا البرنامج

### 1.3 متطلبات الاعتماد — `/accreditation/requirements`

**الغرض:** متابعة جاهزية البرنامج قبل الزيارة + تقرير الدراسة الذاتية.

**شرط الوصول:** متاحة فقط للبرامج التي حالتها "مؤهل للاعتماد" — للبرامج الأخرى تظهر رسالة توضيحية.
**شرط الدخول:** عبر صفحة قائمة البرامج المؤهلة فقط (ليس من القائمة العامة مباشرة).

**القسم الأول — متطلبات ما قبل الزيارة:**

جدول الوثائق المطلوبة يحتوي:
```
- رقم تسلسلي
- اسم الوثيقة / التقرير
- الملف المرفوع (رابط + اسم الملف)
- الحالة: مكتمل / غير مكتمل (Badge)
- تاريخ الرفع (auto عند الرفع)
- تاريخ الاستحقاق (Deadline)
- ملاحظات المراجع (نص — مرئية للبرنامج)
```

منطق الحالة لكل وثيقة:
```
مكتمل (حالة إيجابية) = تم الرفع + تمت المراجعة والموافقة
غير مكتمل (حالة تحذيرية) = لم يتم الرفع، أو توجد ملاحظات، أو تجاوز الموعد
```

قواعد إدارة الملفات:
- دعم رفع نسخ متعددة من نفس الوثيقة (Versioning) دون حذف النسخ السابقة
- عدم حذف أي سجل سابق

الالتزام الزمني — Timeline مرئي يعرض:
- تاريخ الاستحقاق
- الموعد النهائي الإلزامي
- تاريخ الرفع الفعلي

**القسم الثاني — تقرير الدراسة الذاتية:**

شرط الظهور: يُتاح فقط بعد اكتمال جميع متطلبات ما قبل الزيارة (كلها بحالة مكتمل).

البيانات التلقائية (تُجلب من Master Data):
- اسم البرنامج / الكلية / المرحلة / جهة الاعتماد

هيكل التقرير:
```
معيار 1 (Standard 1)
  ├── محك 1.1 → حقل تقييم (1-4) + حقل ملاحظات
  ├── محك 1.2 → حقل تقييم (1-4) + حقل ملاحظات
  └── محك 1.3 → حقل تقييم (1-4) + حقل ملاحظات
  → متوسط المعيار = مجموع التقييمات ÷ عدد المحكات (auto)

معيار 2 (Standard 2)
  └── ...

المتوسط النهائي = مجموع متوسطات المعايير ÷ عدد المعايير (auto)
```

مؤشر الجاهزية (auto):
```
المتوسط النهائي ≥ 3 → "جاهز" (حالة إيجابية)
المتوسط النهائي < 3 → "غير جاهز" (حالة تحذيرية)
```

### 1.4 سجل إجراءات الاعتماد — `/accreditation/actions`

**الغرض:** توثيق رسمي كامل لرحلة الاعتماد من الرفع حتى القرار النهائي.

**قواعد صارمة:**
- السجل يبدأ تلقائياً فور تحويل حالة البرنامج إلى "تحت الإجراء"
- يُدار بالكامل من العمادة (Deanship Only)
- لا يمكن حذف أي سجل أو تعديله بعد إنشائه (Immutable)
- كل سجل مختوم بالتاريخ والوقت الدقيق (Time-stamped)
- مرتبط مباشرة بحالة البرنامج في لوحة التحكم

**الإجراءات الأساسية — المرحلة الأولى (الرفع → الزيارة):**
```
1.  الرفع لجهة الاعتماد
    - حقل إلزامي: تاريخ الرفع
    - أثر: تحويل حالة البرنامج → "تحت الإجراء"
    - الصفحة تصبح Read-only بعد الرفع

2.  اللقاء التعريفي
    - حقل: تاريخ اللقاء + وقته (للمتابعة)

3.  ملاحظات الهيئة
    - حقل: نص الملاحظات
    - مرئية للبرنامج للاطلاع والتوجيه

4.  زيارة التحقق
    - حقل: تاريخ الزيارة المسجّل (إن وُجدت)

5.  تاريخ الزيارة الرسمي
    - الموعد الرسمي المعتمد من الهيئة

6.  الزيارة الميدانية
    - تاريخ الزيارة الفعلية (للمتابعة ما بعد الزيارة)
```

**الإجراءات المتقدمة — المرحلة الثانية (التقرير → القرار):**
```
7.  تقرير الزيارة النهائية
    - استلام التقرير من الهيئة + إرفاقه

8.  نموذج TP-107 — الرد على الملاحظات
    - مسودة البرنامج → مراجعة العمادة
    - حقل: الملف + تاريخ الرفع

9.  نموذج TP-109 — الرفع النهائي (إذا طُلب)
    - حقل: الملف + تاريخ الرفع

10. حالة الاعتماد
    - تحديث الحالة: تحت الإجراء / كامل / مشروط / غير معتمد

11. القرار النهائي
    - نوع الاعتماد: كامل (Full) / مشروط (Conditional) / غير معتمد (Not Accredited)
    - أثر تلقائي: تحديث حالة البرنامج في جميع صفحات النظام
```

**الصلاحيات لهذه الصفحة:**
```
العمادة (Admin):    إدخال وتحديث جميع الإجراءات + تنفيذ القرار النهائي
المراجع (Reviewer): إدخال الملاحظات على التقارير
البرنامج (User):    اطلاع فقط على الإجراءات والملاحظات + إعداد مسودة الرد (لا يرفع مباشرة)
```

### 1.5 مرحلة ما بعد الاعتماد — `/accreditation/post-accreditation`

**الغرض:** ضمان الاستمرارية والجودة بعد الحصول على الاعتماد.

**شرط التفعيل:** تُفعَّل تلقائياً للبرامج الحاصلة على اعتماد كامل أو مشروط.
**الإدارة:** من خلال صفحة واحدة موحدة داخل النظام.
**التفعيل:** تلقائي ومستمر طوال فترة سريان الاعتماد.

**القسم الأول — التقارير السنوية:**

ينطبق على: الاعتماد الكامل والمشروط.

ثلاثة أنواع من التقارير السنوية لكل برنامج:

```
1. تقرير التغييرات الجوهرية
   - الغرض: توثيق التعديلات الهامة في الهيكل أو العمليات
   - الحقول: السنة + الملف + تاريخ الرفع (إلزامي) + ملاحظات المراجع

2. نموذج البيانات الأساسية ومؤشرات الأداء
   - الغرض: جمع البيانات الرئيسية وقياس الأداء مقابل الأهداف
   - الحقول: السنة + الملف + تاريخ الرفع (إلزامي) + ملاحظات المراجع

3. تقرير المتابعة الدورية
   - الغرض: رصد التقدم والالتزام بشكل منتظم
   - الحقول: السنة + الملف + تاريخ الرفع (إلزامي) + ملاحظات المراجع
```

الحقول الموحدة لجميع التقارير: السنة / الملف / ملاحظات المراجع / تاريخ الرفع (إلزامي)

منطق حالة التقرير (Status Logic):
```
مكتمل (حالة إيجابية):
  ✓ تم الرفع + تمت المراجعة + تم إغلاق الملاحظات

غير مكتمل (حالة تحذيرية):
  ✗ نقص في الرفع أو التاريخ أو المراجعة
  → يتطلب إجراء فورياً لاستكمال المتطلبات
```

**الصلاحيات للتقارير السنوية:**
```
البرنامج (Program):    رفع التقارير السنوية + الاطلاع على ملاحظات المراجع
المراجع (Reviewer):    إدخال ملاحظات المراجعة + اعتماد اكتمال التقرير
العمادة (Admin):       متابعة المواعيد + الرفع لجهة الاعتماد + تنفيذ قرار التحويل
```

**القسم الثاني — متابعة الاعتماد المشروط:**

قسم مخصص حصرياً للبرامج الحاصلة على اعتماد مشروط.

الهدف: توثيق إجراءات استيفاء الشروط والمتابعة مع جهة الاعتماد حتى التحويل لاعتماد كامل.

مسار إجراءات الاستيفاء:
```
الإشعار بالاعتماد المشروط:
  1. تاريخ المخاطبة       → إشعار البرنامج ببدء الإجراءات (Program Action)
  2. رقم المعاملة         → التوثيق الإداري الرسمي (Program Action)
  3. موعد تسليم TP-111    → الموعد النهائي الإلزامي للبرنامج (Program Action)
  4. رفع تقرير TP-111     → رفع البرنامج للتقرير / توثيق تلقائي للتاريخ والوقت (Program Action)
  5. ملاحظات المراجع      → التأكد من المعالجة قبل الرفع (Deanery Action)
  6. الرفع الأول للهيئة   → إجراء حصري للعمادة (Deanery Action)

المتابعة مع الهيئة:
  7. موعد المتابعة         → تاريخ للتذكير في حال عدم الرد
  8. تاريخ رد الهيئة       → استلام الرد الرسمي
  9. رفع تقرير TP-111 (بعد الملاحظات) → التقرير المعدّل + تسجيل تلقائي للتاريخ
  10. ملاحظات المراجع (على التقرير المعدّل) → مراجعة نهائية قبل الرفع
  11. تاريخ الرفع الثاني   → في حال طلبت الهيئة معالجة إضافية
```

قرار التحويل النهائي:
```
1. تحويل إلى اعتماد كامل (Full Accreditation)
   → تحديث تلقائي لحالة البرنامج إلى "معتمد كلياً" في جميع صفحات النظام

2. استمرار اعتماد مشروط (Continue Conditional)
   → البرنامج يبقى في حالة الاعتماد المشروط مع متطلبات إضافية

3. عدم التحويل (No Conversion)
   → إيقاف البرنامج أو سحب الاعتماد + توضيح الأسباب
```

الأثر المباشر لكل قرار: تحديث تلقائي لحالة البرنامج في جميع صفحات النظام.

### 2.2 المشاريع الاستراتيجية — `/strategic-planning/projects`

**جدول المشاريع:**
```
- اسم المشروع
- الهدف الاستراتيجي المرتبط
- المسؤول (Project Manager)
- الفريق (أسماء الأعضاء)
- تاريخ البداية
- تاريخ النهاية
- نسبة الإنجاز (Progress Bar)
- الحالة (Badge)
```

فلاتر: الحالة / المسؤول / السنة / الهدف الاستراتيجي.

زر "إضافة مشروع" → Modal أو صفحة بالحقول أعلاه.

**صفحة تفاصيل المشروع** `/strategic-planning/projects/{id}`:

تبويبات (Tabs):
```
تبويب 1 — المعلومات الأساسية
  - جميع بيانات المشروع قابلة للتعديل

تبويب 2 — المراحل والمهام (Phases & Tasks)
  - قائمة بالمراحل، لكل مرحلة:
    - اسم المرحلة + تاريخ البداية والنهاية + الحالة
    - جدول المهام: الاسم / المسؤول / الموعد / الحالة / ملاحظات
  - إضافة مرحلة جديدة
  - إضافة مهمة لكل مرحلة

تبويب 3 — الوثائق
  - رفع ملفات + عرضها + حذفها
  - تاريخ الرفع + المستخدم (auto)

تبويب 4 — سجل التواصل
  - تسجيل الاجتماعات: التاريخ + الموضوع + الحاضرون + القرارات
  - تسجيل المراسلات: التاريخ + الموضوع + ملف مرفق

تبويب 5 — مؤشرات الأداء (KPIs)
  - اسم المؤشر + القيمة المستهدفة + القيمة الفعلية + الفجوة (auto)
  - إضافة / تعديل / حذف مؤشرات
```

### 3.3 مراجعة البرامج الأكاديمية — `/quality-projects/program-review`

**الغرض:** إدارة توصيفات البرامج والمقررات وضمان جودتها.

**إدارة توصيفات البرامج:**
```
لكل برنامج:
- معلومات البرنامج الأساسية
- رؤية البرنامج ورسالته
- أهداف البرنامج
- مخرجات التعلم
- الخطة الدراسية
- أنماط التدريس: تقليدي / إلكتروني
- نوع البرنامج الأكاديمي
- مجال التخصص حسب الإطار الوطني للمؤهلات
- الدرجة العلمية
```

**إدارة توصيفات المقررات:**
```
لكل مقرر:
- معلومات المقرر الأساسية
- مخرجات تعلم المقرر
- طرق التدريس
- طرق التقييم
- الخطة الدراسية الأسبوعية
```

**مشاريع ومراحل تطوير الخطط والبرامج:**
- إنشاء مشروع مراجعة لكل برنامج
- تحديد المراحل والمهام ومسؤولياتها
- تتبع التقدم

**سير العمل للموافقة (Approval Workflow):**
```
مسودة → مراجعة أعضاء اللجنة → موافقة رئيس القسم → موافقة العميد → اعتماد نهائي
```
- في كل خطوة: المسؤول + الحالة + التاريخ + ملاحظات
- تنبيهات تلقائية عند انتهاء مراحل المراجعة

**تتبع التغييرات والنسخ:**
- حفظ جميع النسخ السابقة من التوصيفات
- عرض الفروقات بين النسخ (إن أمكن)
- لا حذف لأي نسخة سابقة

### 3.4 تقويم مخرجات التعلم — `/quality-projects/learning-outcomes`

**الغرض:** منظومة متكاملة لإدارة وقياس مخرجات التعلم على جميع المستويات.

**تعريف المخرجات (3 مستويات):**
```
مستوى الجامعة (Institution Level):
- مخرجات التعلم العامة للجامعة
- خصائص الخريجين على مستوى الجامعة

مستوى الكلية/البرنامج (Program Level):
- مخرجات التعلم الخاصة بالبرنامج
- خصائص الخريجين للبرنامج
- مجالات نواتج التعلم المستخدمة في الكليات

مستوى المقرر (Course Level):
- مخرجات التعلم لكل مقرر
- ربطها بطرق التقييم
- ربطها بالأسئلة في الاختبارات
```

**مصفوفات الربط (Mapping Matrices) — 9 مستويات:**
```
1. خصائص الخريجين (كلية) ← مصادرها
2. خصائص الخريجين (كلية) ← مخرجات التعلم (كلية)
3. مخرجات التعلم (برنامج) ← مخرجات التعلم (كلية)
4. مخرجات التعلم (برنامج) ← خصائص الخريجين (برنامج)
5. مخرجات التعلم (برنامج) ← مخرجات التعلم (مقررات)
6. مخرجات التعلم (برنامج) ← المقررات في البرنامج
7. مخرجات التعلم (كلية + برنامج + مقررات) ← مجالات نواتج التعلم
8. مخرجات التعلم (مقررات) ← طرق التقييم
9. مخرجات التعلم (مقررات) ← الأسئلة في الاختبارات
```
كل مصفوفة: جدول Grid قابل للتعديل — Checkbox أو قيمة رقمية لكل تقاطع.

**إدارة خطط القياس:**
```
خطط القياس على مستوى الكلية:
- تعريف طرق القياس المباشرة وغير المباشرة
- ربط المخرجات بمهام التقييم

خطط القياس على مستوى البرنامج:
- إدارة مهام التقييم على مستوى البرنامج (مثل اختبارات نهاية البرنامج)
- ربطها بالمخرجات
- التحكم في الصلاحيات للوصول

خطط القياس على مستوى المقرر/الدورة:
- تعريف استراتيجيات التدريس + أساليب التقييم + ربطها
- تصدير خطط المقررات لجميع الشعب الدراسية إلكترونياً
- التنوع في خطط القياس المباشرة وغير المباشرة
```

**إدارة نتائج القياس:**
```
- إدخال درجات الطلاب يدوياً أو استيراد من Excel
- ربط الدرجات بمهام التقييم وبالمخرجات
- إضافة شواهد وأدلة على مستوى التقييمات
- إدارة مختلف خطط التحسين على جميع المستويات
- التعاون والمشاركة في تنفيذ عمليات التقويم وأخذ التغذية الراجعة
```

**الحسابات التلقائية:**
```
- حساب نسبة تحقق كل مخرج تلقائياً
- تجميع النتائج تلقائياً: من الشعب → المقرر → البرنامج → الكلية
- مقارنة بمستوى الأداء المستهدف
- سلالم التقدير لتوحيد نتائج القياس والتقويم في مختلف البرامج
```

**أدوات التقييم:**
```
- مصفوفة الأداء (Rubric)
- الاختبارات وربط أسئلتها بالمخرجات
```

**لوحات المعلومات والتقارير:**
```
- لوحة معلومات لكل برنامج تشمل كل ما يتعلق بمخرجات التعلم
- لوحة لتتبع تحصيل الطالب لنتائج المخرجات على مستوى المقررات
- تقارير نتائج القياس على مستوى: مهام التقييم / الشعب / المقررات / البرامج / الكلية
- خطط التحسين المستمر على مستوى الكلية والبرامج والمقررات
```
